# Making Parts of a Mailchimp Template Editable in the Web Admin UI

**What this covers:** the HTML markup to put in a Mailchimp classic (coded/HTML) template so a human can edit headings, paragraphs, or images by hand in Mailchimp's Web Admin editor, or hide a whole block with one click.

**What Mailchimp's Web Admin checks for:** two special HTML attributes that don't do anything visually — they're instructions to the Mailchimp editor.

- `mc:edit="some-name"` — makes an element clickable/editable in the editor.
- `mc:hideable="some-name"` — gives an element a hide/delete control, so the whole block can be removed with one click.

Every name must be unique within the template. Anything without either attribute is permanently locked — visible, but not editable in the UI.

This is the how-to companion to [API-NOTES.md](../API-NOTES.md) — this doc says what markup to write; API-NOTES.md documents *why* each rule holds, with the testing behind it. Don't update one without checking the other. Each section below is a standalone recipe.

## 1. Make a heading editable

**Goal:** a user can click a headline (`<h1>`, `<h2>`, etc.) in the editor and change the wording.

**How:** put `mc:edit="a-unique-name"` directly on the heading tag itself. Size/font/color can be carried either as inline styles on the heading tag or as nested `<span>`s inside it — both render correctly for a heading (see API-NOTES.md's "editor-pane rendering rules" for why). This repo's own `template.html` uses the nested-`<span>` form, generated by `make_template.py`'s `_heading()`:

```html
<h2 style="text-align: left;" mc:edit="sermon_title">
  <span style="font-size: 26px"><span style="font-family: Arial, sans-serif;">
    This is a Heading 2
  </span></span>
</h2>
```

A single inline-styled tag with no spans works too:

```html
<h2 mc:edit="sermon_title" style="font-family:Arial,sans-serif; font-size:22px; color:#222;">
  This is a Heading 2
</h2>
```

**Avoid:**

- Putting a `<table>` or other layout markup inside the heading region.
- Confusing this with the body-text rule below — a heading tolerates nested spans; a `<p style="…">` block does not (section 2).

## 2. Make a paragraph / text block editable

**Goal:** a user can click into a chunk of body text and edit the wording, including any links inside it.

**How:** put `mc:edit="a-unique-name"` on a `<div>` (not a `<p>`), with all font styling inline on that `<div>`. For more than one paragraph, separate them with `<br><br>` inside the same `<div>` rather than multiple `<p>` tags.

```html
<div mc:edit="announcement_text"
     style="font-family:Arial,sans-serif; font-size:15px; line-height:22px; color:#333;">
  Join us this Sunday for a special guest speaker.<br><br>
  Doors open at 9:30am.
</div>
```

**Links inside an editable text block:** keep them bare — no `style` attribute on the `<a>`, and no `<span>` nested inside it.

```html
<a href="https://example.org/details" target="_blank">See details</a>
```

**Avoid — each of these silently breaks the editable pane** (details and testing in API-NOTES.md's "editor-pane rendering rules"):

- Using `<p style="…">` as the block's own tag instead of `<div>`.
- Putting a `<table>` inside the text block.
- Styling a link (`<a style="…">`) or wrapping link text in a `<span>`.
- A CSS rule elsewhere in the template's `<style>` block that targets *only* links (a selector like `a { … }` or `.foo a { … }` with nothing else in that rule) — fix by adding other selectors to the rule so it's no longer link-only, not by deleting it outright (that breaks layout elsewhere).

## 3. Make an image's properties editable

*Replace the image / edit Alt text / add a link*

**Goal:** a user can click an image in the editor and get the real image toolbar — Replace image, edit Alt text, edit the click-through link.

**How:** put `mc:edit="a-unique-name"` **directly on the `<img>` tag itself** — nowhere else.

```html
<img mc:edit="hero_image" src="https://example.org/hero.jpg" alt="Training" width="600">
```

**The one rule that matters most here:** no element containing the image — no surrounding `<td>`, `<div>`, `<a>`, or table row — can also have `mc:edit`. If any container has its own `mc:edit`, the image toolbar disappears, replaced by a generic empty edit box, even if the `<img>` itself is tagged correctly (why: API-NOTES.md's "Image regions: the central trap").

```html
<!-- WRONG — the outer div's mc:edit blocks the image toolbar -->
<div mc:edit="hero_block">
  <img mc:edit="hero_image" src="https://example.org/hero.jpg" alt="Sunday service">
</div>

<!-- RIGHT — only the image itself is tagged -->
<div>
  <img mc:edit="hero_image" src="https://example.org/hero.jpg" alt="Sunday service">
</div>
```

**⚠ Replacing an image by hand in the editor deletes its Alt text and width.** Re-type the Alt text *after* replacing — it doesn't carry over (API-NOTES.md's "Image regions" section).

## 4. Make a whole block deletable (hide / remove with one click)

**Goal:** a user can click a "hide" control in the editor and remove an entire block — e.g. an image, its caption, and a divider together — with one click, and have it actually removed from the sent email (not just hidden visually).

**How:** wrap the whole group in a container (a `<table>` row, `<tr>`, or `<div>` — whatever already wraps that group) and put `mc:hideable="a-unique-name"` on that wrapper. Do **not** also put `mc:edit` on the same wrapper.

```html
<tr mc:hideable="announcement_block">
  <td>
    <img mc:edit="announcement_image" src="https://example.org/promo.jpg" alt="Special event">
    <div mc:edit="announcement_text" style="font-family:Arial,sans-serif; font-size:15px;">
      Details about the event go here.
    </div>
  </td>
</tr>
```

**Avoid:**

- Adding `mc:edit` to the same wrapper that has `mc:hideable` — blocks any image inside it from getting its Replace/Alt toolbar (section 3).
- Adding a *second* `mc:hideable` control to something already inside a hideable group — one hide control per group is enough.

**After hiding a block, double check the plain-text version of the email** before sending (why this can leak content even after hiding: API-NOTES.md's "`mc:hideable` and hidden-block removal").

## 5. Lock a block (no editing, no hiding)

**Goal:** the block never changes — no click-to-edit, no hide control.

**How:** don't add `mc:edit` or `mc:hideable` to it. This is the default for anything left untagged.

## Before you start: check the template type

All of the above only works on a **coded/HTML template** — what Mailchimp calls "classic," as opposed to the newer drag-and-drop builder. If a template was built with the drag-and-drop designer, `mc:edit` and `mc:hideable` do nothing (why: API-NOTES.md's "Classic (legacy) builder vs. the new builder").

To check: look at the template's info in Mailchimp — it should not be a drag-and-drop template. With API/developer access, check the template's `drag_and_drop` field is `false`.

## Quick reference

| I want to... | Where the attribute goes | Watch out for |
|---|---|---|
| Edit a heading's text | `mc:edit` on the heading tag itself; inline styles or nested `<span>`s both work | Layout markup (e.g. a `<table>`) inside the region |
| Edit a paragraph's text | `mc:edit` on a `<div>` (not `<p>`), styles inline, `<br><br>` between paragraphs | `<p>` tags, tables inside the block |
| Edit a link inside text | No special attribute needed — just keep the `<a>` bare | Styled `<a>`, or a `<span>` inside the `<a>` |
| Replace/edit an image | `mc:edit` on the `<img>` tag only | Any container around it also having `mc:edit` |
| Hide/delete a whole block | `mc:hideable` on the group's outer wrapper | Also adding `mc:edit` to that same wrapper |
| Lock a block completely | No attribute at all | — |
